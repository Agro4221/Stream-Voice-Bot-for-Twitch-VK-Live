# Stream Voice Bot — история изменений
## 1.1.11
- Для STT добавлен выбор устройства: «Авто (CUDA → CPU)», «GPU (NVIDIA CUDA)» или «CPU int8».
- В режиме «Авто» CUDA пробуется первой, а при недоступности выполняется CPU fallback.
- Изменение модели или устройства STT теперь безопасно применяется при следующем запуске и не обнуяет активную модель посреди распознавания.
- Восстановлена низколатентная обработка STT для субтитров: окно 2,5 сек и overlap 0,25 сек.
- При отставании распознавания теперь берётся самое новое аудио, а старый накопившийся backlog не проигрывается по кругу.
- Локальный перевод субтитров выполняется в отдельном потоке и не блокирует следующий цикл распознавания.
- Для существующих установок с 4,0/0,5 добавлена однократная миграция обратно на 2,5/0,25.
- Сохранены VAD, beam 1, `condition_on_previous_text=False` и удаление экспериментального `without_timestamps=True`.
- Подготовлена переносимая Windows EXE-сборка с встроенной моделью Silero и runtime Node только для VK bridge.
- Для EXE автоматизировано одноразовое создание ярлыка рабочего стола при первом запуске; отдельный скрипт создания ярлыка удалён.


## Текущая версия

### 1.1.11
- STT: режимы Auto/GPU/CPU, диагностика устройства и микрофона.
- STT: локальный GPU runtime для CUDA 12 + cuDNN 9 с установкой по требованию.
- OBS subtitles: отдельные дорожки, прямой тест дорожки и защита от Whisper credit-hallucinations.
- Windows EXE: компактная onedir-упаковка с _internal и сокращённым количеством файлов.

### 1.1.10
- Исправлена обработка Clear queue: API возвращает число удалённых элементов.
- Админка показывает результат очистки очереди.
- Добавлен детерминированный регрессионный тест очереди.

### 1.1.8
- Упрощён Windows-запуск: один пользовательский `start_bot.bat`.
- Launcher передаёт запуск бота отдельному скрытому PowerShell-процессу и сразу закрывает CMD.
- Добавлена запись ошибок launcher в `.runtime\\launcher.log`.
- Добавлена обязательная проверка синтаксиса PowerShell launcher в CI.
- После готовности локальной админки окно CMD автоматически закрывается.
- Диагностика и журналы доступны из самой админки.
- Удалены дублирующие launcher BAT и старые отдельные release-notes.

## Предыдущие версии

### 1.1.4
- Исправлены кнопки `Pause`, `Resume`, `Stop`, `Skip` и `Clear queue` в админке: они используют корректные POST-запросы.

### 1.1.3
- Исправлен Windows STT для WASAPI/WDM-KS: COM инициализируется в рабочем аудиопотоке перед открытием устройства.

### 1.1.2
- STT получил fallback на системное устройство ввода Windows, если сохранённый input не открывается.

### 1.1.1
- В launcher добавлена явная предварительная проверка запуска приложения и зависимостей, чтобы ошибки не скрывались.

### 1.1.0
- STT сначала пытается использовать native/default формат аудиоустройства, затем fallback по частотам и каналам.
- Twitch озвучивает только события Channel Points redemption; обычный чат не используется как источник TTS.
- VK озвучивает только распознанные объявления о награде с текстом для озвучки.
- Добавлены регрессионные проверки для новых сценариев.

### 1.0.7–1.0.9
- Усилен fallback STT для Windows-аудиоустройств.
- VK bridge переведён на поддерживаемый `vklive-message-client`.
- Исправлена нормализация URL каналов VK Video Live.
- Добавлена миграция старых SQLite-схем истории чата без удаления существующей базы.
- Добавлена поддержка WASAPI auto-convert в окружении STT.
- Улучшена обработка Twitch redemption API, в том числе отдельная обработка запрета обновления redemption со стороны Twitch.
- Добавлены тесты для этих сценариев.

### 1.0.6
- Админка автоматически открывается после готовности локального сервера.
- Добавлено штатное завершение работы из админки.
- Добавлена диагностика runtime-событий в самой админке.

### 1.0.5
- Добавлен тихий Windows launcher и штатный lifecycle локального сервера.

### 1.0.4

### 1.0.2

## Примечания

- Модель `v5_ru.pt` не хранится в Git и скачивается установщиком отдельно.
- VB-CABLE устанавливается отдельно как системный аудиодрайвер.
- Секреты Twitch/VK не должны попадать в репозиторий.
- Подробное описание установки, настроек и архитектуры находится в `README.md`.
